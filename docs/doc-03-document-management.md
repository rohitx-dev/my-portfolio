# DOC-03: Owner uploads, downloads, and visibility

## Apply this batch

Start from merged PR #15 on `main`. Create issue **DOC-03: Owner uploads, downloads, and document visibility** and branch `feat/doc-03-document-management`.

The issue scope is:
- Owner-only uploads to the existing private bucket.
- File validation: PDF, TXT, DOCX, JPG, PNG; maximum 10 MB.
- New documents private by default.
- Owner downloads and explicit public/private controls.
- Real public records and downloads on `/docs`.
- Loading, empty, error, and retry states.

Acceptance criteria: owner can upload and download; signed-out visitors cannot upload/change visibility/read private files; public documents are downloadable without login; making a file private blocks new public links; failed uploads never produce public records; checks pass.

Visitor submissions, editing document details, and deletion are out of scope.

Upload the patch next to `package.json`, then run:

git apply doc-03-document-management.patch

No new packages, environment variables, or SQL migrations are required. Keep the existing bucket private. Keep the Codespaces Server Actions development origin settings from DOC-02.

## How it works

1. The owner fills in a name, optional description, and file.
2. A Server Action verifies the owner and validates metadata, then issues a signed upload token for a new UUID path beneath the owner UID. Existing files cannot be overwritten.
3. The browser sends the file directly to Supabase Storage. The bytes do not pass through a Vercel function or Server Action request, avoiding their body size limits. Supabase also enforces the configured bucket type and size limits.
4. A second Server Action verifies stored size and MIME metadata, then inserts the document record with private visibility. There is no public record before this succeeds.
5. If saving fails, the form keeps the receipt and offers **Retry saving** without uploading a second copy. If the save succeeded but its response was lost, the same ID is recognized on retry.
6. **Make public** asks for confirmation and updates only that owner's record. **Make private** removes it from new public queries.
7. `/docs` uses a session-free client and RLS to read public records, with no data cache. The owner also sees only public records on this page.
8. Download links target `/docs/[id]/download`. Each request checks the document's current access rules. Private downloads additionally validate the owner session. Allowed requests redirect to a 60-second signed Storage download URL using the original filename.

## Live acceptance checks

Use non-sensitive test files for the first run.

1. In the owner dashboard, upload a small PDF. Confirm it shows **Private** and downloads with its original filename.
2. In an incognito window, `/docs` must not show that file. Paste its `/docs/<id>/download` link there: it must not download the private file.
3. Click **Make public** and confirm. Refresh incognito `/docs`: the card must appear and download without login.
4. Click **Make private**. Refresh incognito `/docs`: the card must disappear. Request the app's download route again: access must be denied.
5. Check a supported file larger than 4.5 MB but no larger than 10 MB on the Vercel preview, to verify direct upload/download works beyond Vercel function payload limits.
6. Reject an empty file, a file larger than 10 MB, and an unsupported extension. No document should be published.
7. Check a filename containing spaces or Unicode. Check mobile form/card layout.
8. Sign out and verify the owner dashboard still redirects to `/login`.
9. Run the automated test command, lint, and build before the PR.

## Limits and recovery

- Signed upload tokens are valid for two hours under Supabase's API. Treat them as temporary capabilities and never log or share them.
- Download links generated by this app expire after 60 seconds. Already issued links can work until expiry, even after making a file private. A file that someone already downloaded cannot be recalled. Other clients may issue links under Supabase's public-file access rules; this app does not promise retroactive revocation of those links.
- If you leave/reload during an upload failure after the file reached Storage but before its record was saved, an unlisted private object can remain. It cannot be downloaded anonymously because no public record exists. Its path is `<owner UID>/<document UUID>`. Review unlisted objects in the Supabase Storage dashboard before manually removing any. Do not remove files referenced by existing document records.
- File type checks compare filename, MIME declarations, and Storage metadata. They are not malware scanning or deep content inspection. Visitor uploads will need their own approval and abuse controls in a later issue.
- Lists display the 50 most recent records. Pagination and file deletion are later work.
- Automated tests mock service boundaries; live Supabase and browser checks above are still required before merge.
- Dependency audit warnings are left unchanged as requested.
